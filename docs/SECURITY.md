# Security notes
Implemented: CSP and security headers; same-origin socket check; crypto-random 8-char codes (40 bits), 5-min TTL, single-use, 2-device limit; per-IP rate limits on create/join/signal and connection caps; strict signaling validation; 32 KB socket message cap; session sweep; untrusted-input handling for filenames (path/bidi/reserved names, de-duplication) and manifests; SHA-256 verification; no auto-open of received files; risky-extension warning; server-side 401 gates for admin/wallet/withdrawal routes; no secrets in frontend.
Not yet: HTTPS termination (do it at your proxy), authentication, RBAC, database, audit logs, reward fraud checks, payment webhooks, abuse detection beyond rate limits. Pairing codes are 40-bit: rate limiting is what makes guessing impractical; keep it on.
Known limits: SDP exposes network addresses to the paired peer (inherent to WebRTC); file names are sent to the receiver before acceptance; in-memory fallback limits file size; sender-reported results are never trusted for rewards (design requirement for Phase 4).
